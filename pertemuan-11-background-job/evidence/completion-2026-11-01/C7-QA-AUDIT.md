# Audit read-only C.1–C.6 dan kontrak log C.7

## 1. Lingkup dan kesimpulan sementara

Audit ini mengikuti prioritas pengguna terbaru yang diteruskan Main Agent: meninjau evidence C.1–C.6, khususnya error Redis pukul 22:42:46 dan relay_delayed context canceled pukul 23:02:10 pada 1 November 2026. QA hanya membaca file aman, source, dan snapshot yang sudah tersedia; tidak mengendalikan runtime, database, layanan atau UI. File ini satu-satunya keluaran yang ditulis untuk audit tersebut. Tidak ada .env, password/token, dump privat atau isi logs/ aktual dibuka.

Kesimpulan utama: empat error 22:42:46 membuktikan operasi internal Asynq mengalami timeout I/O ke Redis pada saat itu, tetapi tidak membuktikan Redis dimatikan atau kehilangan task. Warning 23:02:10 menunjukkan pembatalan context saat memulai transaksi relay; urutan berikutnya justru menunjukkan task outbox 56 berhasil diproses lalu aplikasi berhenti rapi. Keduanya tidak boleh digabung menjadi satu bukti Redis gagal sampai akhir. C.7 belum layak dinyatakan PASS penuh: ada relay_delayed saat pembatalan context, padahal PDF mensyaratkan log itu hanya ketika Redis bermasalah, dan cakupan lengkap ketiadaan request_failed C.1–C.6 serta queue akhir C.6 belum tersedia dalam artifact publik yang ditemukan.

## 4. Analisis pembatalan context dan hubungan shutdown

Source `main.go` membentuk context melalui signal.NotifyContext untuk os.Interrupt/SIGTERM, menunggu ctx.Done, lalu memanggil stopWorker dan menulis pesan berhenti rapi. `worker.go` menjalankan relay memakai context itu, menunggu relayDone, kemudian srv.Shutdown dan menutup client. `outbox_relay.go` memanggil RelayOnce sebelum memeriksa ctx.Done pada ujung loop, dan mencatat setiap error RelayOnce sebagai relay_delayed. `app/repository/tx.go` membungkus kegagalan pool.Begin(ctx) sebagai `memulai transaction: ...`.

Rangkaian source tersebut menjelaskan bagaimana cancellation yang bertepatan dengan putaran relay dapat menghasilkan `memulai transaction: context canceled`: context sudah dibatalkan sebelum transaksi baru berhasil dimulai, sehingga callback transaksi relay belum dijalankan pada percobaan itu. Ini bukan pesan enqueue Redis dan tidak membuktikan event hilang. Hubungannya dengan shutdown didukung urutan warning, processed, dan clean-stop. Pemicu persis cancellation tetap tidak terekam sebagai timestamp signal di transcript; Ctrl+C berasal dari konteks skenario/handoff dan pesan PowerShell, bukan pembacaan event signal yang presisi oleh QA.

`The pipeline has been stopped` berasal dari transcript shell setelah aplikasi menulis clean-stop. Pesan itu tidak boleh langsung diklaim sebagai panic aplikasi, kegagalan database, atau bukti email dibatalkan. Sebaliknya, pesan clean-stop juga bukan pengganti exit code proses ataupun query notifikasi final. Kedua batas ini harus dipertahankan.

## 5. Kontrak C.7: field dan cakupan

PDF hlm. 33–34 mengharuskan relay_done/published, relay_delayed/published/error hanya saat Redis bermasalah, notification_processed/outbox_id/event/retry/already_sent, task_failed/type/attempt x/6/error, serta tidak ada request_failed API sepanjang C.1–C.6. QA memparse events tersimpan pada lima snapshot terpilih, tanpa membaca log aktual:

1. C.2 off state: 134 relay_delayed, seluruhnya memiliki published/error. C.2 settled: 174 relay_delayed, satu relay_done dan tiga notification_processed, seluruh field wajib ada.
2. C.3 after07: enam relay_done, enam notification_processed, dua task_failed; seluruh field wajib ada.
3. C.4 after08: satu relay_done dan satu task_failed; field wajib ada.
4. C.5 checkpoint: satu relay_done dan enam notification_processed; field wajib ada.

Tidak ada request_failed pada array events lima artifact yang diperiksa. Sebagian snapshot berisi selected event types atau window terbatas, sehingga hasil nol tersebut tidak membuktikan ketiadaan request_failed pada seluruh log API C.1–C.6. Tidak ada klaim proses worker/API berasal dari field proses yang tidak ada pada setiap baris; identitas producer juga bergantung source, metadata runtime dan konteks artifact.

Warning relay_delayed 23:02:10 secara nyata berada di luar pengertian “hanya saat Redis bermasalah”: error-nya adalah pembatalan transaksi PostgreSQL/context ketika shutdown, bukan Redis. Maka syarat khusus C.7 ini mempunyai mismatch yang terbukti pada transcript, meskipun shutdown tampak menyelesaikan task aktif. Jangan menyembunyikan warning, mengubah log lama, atau menyatakan C.7 penuh PASS atas dasar penjelasan bahwa warning dapat dipahami. Perbaikan klasifikasi/suppression cancellation yang disengaja hanya boleh dilakukan pemilik source dalam lingkup pekerjaan yang disetujui dan memerlukan bukti ulang yang relevan; QA tidak mengubah source.
